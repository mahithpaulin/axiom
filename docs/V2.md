# Axiom V2 — full capability upgrade

V1 is the base: one logical IR (`Program`), two engines (bottom-up
saturation, SLD), a CDCL SAT core (II1), and difference-logic +
congruence theories (II2a). V2 keeps that base untouched and adds the
capability rows of ROADMAP Stage 2 (II2b–II6) as **new representations
with new operations**, all under one roof.

## 1. The idea in one paragraph

Every request — a puzzle, a word problem, a chess position, a plan —
is compiled into a **set of representations**, and every representation
supports a fixed set of **logical operations**. The client turns their
request into the logical language (text or the `Builder`-style API),
picks the operation, and gets back a `Status` plus a checkable
certificate. Same honesty contract as V1: a definite answer carries a
proof; anything else is `Exhausted` or `Unknown`.

## 2. The representation set

| # | Representation | Module | Holds | Lowered to / solved by |
|---|---|---|---|---|
| R1 | `Program` (V1 IR) | `program` | facts + stratified rules | `saturate`, SLD (V1, unchanged) |
| R2 | Clause set | `sat` | ground CNF over `Lit` | CDCL core (V1, unchanged) |
| R3 | Theory formula | `theory` | RDL + UF atoms | DPLL(T) driver (V1, extended II2b) |
| R4 | Finite-domain CSP | `csp` | vars, domains, constraints + explanations | MAC backtracking (new, II3) |
| R5 | State graph | `state` | states, actions, costs, goals | BFS/Dijkstra + BMC lowering to R2 (new, II4) |
| R6 | Search graph / game tree | `search` | explicit graph + heuristic; game tree + eval | A\*, IDA\*, alpha-beta + transposition (new, II5) |

`src/repr.rs` is the spine: `Representation` names one of R1–R6,
`Operation` names what to do (`Deduce`, `Satisfy`, `Propagate`,
`Plan`, `ShortestPath`, `Play`), and `run` dispatches to the solver
for that pair. Adding a domain (chess, go, sudoku, scheduling, word
problems) costs an **adapter into R1–R6, never a core change** — that
is the V2 acceptance test, same as ARCHITECTURE §8.

## 3. The logical language

The exterior stays the only place with domain knowledge. V2 extends
its surface so each representation is writable as text:

```text
# R4: a puzzle is domains + constraints
domain x = {1, 2, 3, 4}.
constraint all_different([x, y, z]).
constraint x + 2*y <= 5.

# R5: a planning problem is states + actions + goals
state s0. state s1. action a : s0 -> s1 cost 1.
initial s0. goal s1.

# R6: a game is positions + moves + evaluation
position p0, turn max. move m1 : p0 -> p1. eval p1 = 10.

# operations
?- solve.        # R2/R3/R4
?- plan(bound 5).# R5
?- play(depth 3).# R6
```

The text above is the target, landed slice by slice; the Rust API in
`csp` / `state` / `search` / `repr` is authoritative until the parser
catches up. `docs/LANGUAGE_SPEC.md` records exactly which lines parse
in each slice — no aspirational grammar.

## 4. What V2 covers (operation matrix)

| Request | Representation | Operation | Certificate |
|---|---|---|---|
| Sudoku, zebra, logic grid, scheduling | R4 | `Propagate` | assignment re-checked by `verify_csp`; `Impossible` carries the pruning trace |
| Word arithmetic ("x is twice y…") | R4 linear bounds + R3 | `Propagate`/`Satisfy` | model re-evaluated independently |
| Blocksworld, gripper, logistics | R5 | `Plan` | plan replayed step by step (`verify_plan`) |
| Bounded game solving, puzzles-as-SAT | R5 → R2 | `Satisfy` | SAT model / RUP proof (V1 machinery) |
| Shortest routes, optimal plans | R6 | `ShortestPath` | path re-walked, cost re-added |
| Chess endgames, small-board go captures | R6 game tree | `Play` | principal variation + bound that excludes better replies |
| Full chess games (fixed-depth heuristic play) | `chess`+`chess_play` | `best_move`/`play_game` | move list replayed for legality; mate/draws detected, never assumed |
| Engine choice once several win somewhere | `repr` chooser | any | pure function of input features (deterministic) |

Chess and go on full boards are *not* claimed: the tree is explicit
and bounded, so full-board play is `Exhausted` past the budget, never
a guessed move. Endgames and small boards are in scope; anything
bigger reports the bound honestly.

## 5. Proof discipline per representation

- R4: `Found` carries the assignment; `verify_csp` re-evaluates every
  constraint from the text of the problem, sharing no code with the
  propagators. `Impossible` carries the explanation trace (which
  constraint removed the last value of which variable).
- R5: `Found` carries the action sequence; `verify_plan` replays it
  from the initial state. `Impossible` carries the explored-state
  count plus the fixpoint argument (every reachable state visited).
- R6: `Found` carries the path / principal variation; checkers
  re-walk it. Optimality claims carry the bound (closed list for A\*,
  f-limit schedule for IDA\*, alpha-beta window) that excludes
  anything cheaper.
- R2/R3 certificates are V1's and unchanged.

## 6. Landing plan (rapid slices, Actions-verified)

1. **Spine + CSP + state + search skeletons that already solve.** Real
   backtracking with explanations, real Dijkstra + BMC lowering, real
   A\*/IDA\*/alpha-beta — small and slow is fine; missing is not.
2. **II3 propagators**: all-different (Régin-lite → full), bounds,
   table constraints; puzzle adapters (sudoku, zebra) + corpus.
3. **II2b arithmetic**: linear integer layer over the DPLL(T) driver;
   word-problem adapters.
4. **II4/II5 adapters**: blocksworld/gripper/logistics, chess-endgame
   and go-capture trees, planning/sat agreement tests.
5. **II6 chooser + docs**: deterministic strategy selection, V2
   language completion, PERFORMANCE entries.

Every slice is a pushed commit verified by GitHub Actions (the only
compute used). No slice may break `cargo test`, `cargo clippy -D
warnings`, or `cargo fmt --check`. Raw capability first; constants
and asymptotics later — but never at the cost of the status contract.

## 7. Landed (2026-10-04, branch `v2`, PR #1 — all Actions jobs green)

- Slice 1: `csp` (propagation with explanations), `state` (Dijkstra +
  BMC lowering), `search` (A\*/IDA\*/alpha-beta), `repr` (the spine),
  `tests/v2.rs`.
- Slice 2: `AbsDiffNe` + `puzzle` adapters (9x9 sudoku, N-queens,
  map coloring, logic grids).
- Slice 3: `word` front end (named quantities, linear relations).
- Slice 4a: `chess` (legal movegen incl. castling/en passant, FEN,
  perft 20/400/8902, mate-in-1, explicit tree export to `Play`).
- Slice 4b: `go` (liberties, suicide refusal, simple ko, capture
  puzzles) + `domains` (stacking, gripper) with plan-vs-BMC agreement
  tests.
- Slice 5: `choose` (deterministic strategy selection), `examples/`
  (sudoku, queens, chess_mate, go_capture, plan), CI `examples` job.

## 8. Deliberately not yet (next after the merge)

- V2 text language in the exterior (`domain`/`constraint`/`state`/
  `position` directives in §3): the Rust API is authoritative until the
  parser catches up; `LANGUAGE_SPEC.md` will record the exact grammar.
- Full linear arithmetic / Simplex (II2b remainder) for unbounded
  integers; `word` stays range-capped until then.
- Table constraints and a Régin-strength all-different (II3 remainder).
- Fifty-move / threefold repetition draws in `chess`; Chinese scoring
  in `go`; larger planning instances.
- Measured per-engine win regions for the chooser (II6 remainder).
